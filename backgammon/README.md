# Backgammon

A static, board-first family at <https://mathewseng.github.io/backgammon/>. Real entry points: `play/`, `trainer/`, `solver/`, `library/`. No framework or application build step. Development-only Playwright is pinned in the root package manifest.

## Architecture and controls

- `core/table.mjs`: automatic forced turns, committed takeback validation, and replay of previously revealed dice; shared by local and online tables.
- `core/play-session.mjs`: local controller assignments, Play/Solver handoff context and opponent-move markers; no rule-state mutation.
- `core/rules.mjs`: pure state validation, complete-turn enumeration, movement, opening roll, cube, match/Crawford scoring and replay. No random generation inside transitions. Live dice use cryptographic rejection sampling; tests inject a seeded source.
- `core/xgid.mjs`: strict standard XGID parsing/serialization. Uppercase is Ivory (GNU player 1); fields include dice, cube, turn, score, match and Crawford. Rejects unsupported flags rather than guessing.
- `core/protocol.mjs` and `play/network.mjs`: host-authoritative protocol over the unchanged `shared/peer-room.js`.
- `ui/board.mjs`, `ui/shell.mjs`, `ui/analysis.mjs`, `styles.css`: one SVG board, shared draft controller, semantic controls, dialogs, settings and analysis display.
- `core/appearance.mjs`, `ui/appearance.mjs`: validated board palettes and the live color editor. One allowlist of color roles drives SVG pieces, move affordances, dice and player markers; game state and engine cache keys are independent of appearance.
- `engine/`: pinned GNUbg, dedicated module worker, full-context adapter and a single-worker priority queue. Worker termination implements actual cancellation. Pending work is rejected; stale UI results are discarded. LRU cache is limited to 64 complete results; queue to 32 jobs. No unbounded persistent evaluation cache.
- `core/storage.mjs`: version-1 IndexedDB for items, recoverable work and spaced-review progress. Small display preferences use `backgammon.v1.*` localStorage. Notes/names are text, never HTML.

Ivory moves from canonical point 24 toward 1; Teal the opposite way. `points[0]` is Ivory's point 1, with positive Ivory and negative Teal counts. `bar` and `off` are indexed `[Ivory, Teal]`. Orientation changes rendering only. `turn` always identifies the original player on roll. `decisionPlayer(state)` identifies the current responder, including alternating beaver/raccoon offers; `pending.depth` is 0 for an ordinary double, 1 for a beaver and 2 for a raccoon. A pending offer doubles the current accepted `cube.value`. `dice` stores the original pair; doubles expand only during move generation. `sequence` increases on committed actions. Match length zero means an unlimited points session. The explicit schema also includes cube ownership, scores, Crawford history, phase, pending offer, game number and result.

Ringed checkers identify legal sources. Tap/click a source and then a highlighted destination, or drag a checker onto one. Landing rings and destination badges show every reachable distance using one die, both dice, or up to all four dice with doubles. Shortcuts are valid prefixes of complete legal turns; blocked intermediate points cannot be skipped. For a combined move using the same dice, a single hitting route is chosen automatically; quiet equivalent routes need no prompt. Different hitting outcomes still offer a route choice. Move through an intermediate point manually to deliberately avoid a hit. Choices that consume different dice retain an explicit die/route choice. Invalid drops cancel without changing the draft; Escape and pointer cancellation also release the checker safely. If both dice can bear off to the same tray, choose the die in a dialog or set a preferred die. Tap a moved checker and its orange original-position target, or drag it back, to restore its entire journey, dice and any hit checker. Orange targets refer only to its pre-roll origin; intermediate stops and journeys containing a compulsory prefix are excluded. Undo still removes an individual chosen step. Checker revisions show every legal placement using that checker’s own dice plus any unused dice, including partial chains and doubles. For example, both bar/24/20 and bar/21/20 with 1–4 can revise to either 21 or 24; 16/11/8 can revise to 11 or 13. Other checkers’ steps and the original compulsory prefix stay fixed. These legal revisions are highlighted and clickable even before selecting a checker. Unrelated draft steps remain when legal. After the last checker enters from the bar, it stays selected: forward destinations remain visible and **↔ plus a dice total** marks a revised journey. Tap that target or drag the checker there to revise its placement; the entire draft is replayed to restore dice and hits correctly. The Details move selector offers the same entry change. These shortcuts are only offered when the revised draft remains a prefix of a complete legal turn; blocked entries, maximum dice use and the higher-die rule still apply. If checkers remain on the bar, the next bar checker stays selected. Strong selection rings, contrasting ring backings and foreground point washes remain visible over board patterns; return targets use one clean outline in the undo color. Undo removes one chosen step; Reset clears the chosen draft steps while keeping a compulsory entry prefix. These controls affect only unconfirmed moves. Large, high-contrast pip dice sit in the board’s central lane; used dice dim and receive a check mark. Confirm submits a chosen legal turn. A roll with only one legal resulting position plays automatically, including blocked passes and forced bearoffs; equivalent dice orders do not create a choice. Forced turns cannot be taken back with ordinary Undo and need no engine evaluation or confirmation. Compulsory prefixes play automatically before a genuine choice; an unavoidable continuation after a chosen step fills the preview, but the whole chosen turn still waits for Confirm. Undo, Reset and checker revisions do not silently refill that continuation. Explicit local practice dice edits can replace even a forced roll. The accessible move selector in Details offers every legal next step. Board controls use one Tab stop, spatial arrow navigation, Enter and Space. Checker moves, hits and undo use short, interruptible motion; opponent moves replay their committed steps and yield immediately to the next action. Reduced motion removes these transitions. Point targets are deliberately distinct; on phones they are **not** 44 pixels wide. The alternative selector provides larger targets. Settings → Display & controls persists point numbering, orientation and motion preference. Browser zoom remains enabled.

Selecting a checker limits move highlights to its forward routes, alternate first-die moves and undo destinations. A movable checker disc selects (or deselects if already selected), without auto-moving or undoing. An immovable disc passes through to its point’s highlighted destination, if any. Open point space plays a selected legal route; without selection, it uses the nearest legal incoming checker, then an available draft return. Otherwise it selects a movable resident or quietly preserves the existing selection. No unavailable click changes status text. Repeated point-area clicks can build a point while the arrival remains legal, including doubles. There is no timed double-click mode: fast and slow clicks follow identical rules. After a forward move completes the draft, its reversible landing remains selected so the next tap deselects. Shift+point keys explicitly request destination input; ordinary keys retain source selection and the unambiguous undo-only shortcut. Holding a key does not count as repeated presses. The [public controls guide](https://mathewseng.github.io/backgammon/controls/#cases) lists 31 interaction cases alongside click and highlight flowcharts.

## Engine, evaluation and licensing

Upstream: <https://github.com/ascottix/gnubg-core>, pinned to `955555c69adebb1d7de23abc1018074158621168`, web binding **bg4**. Distributed loader/WASM/data are built with **Emscripten 4.0.15**, `-O2`, no pthreads. Cross-origin isolation is unnecessary. The data archive contains neural weights, bearoff databases and Kazaross-XG2 match-equity data. Asset checksums and detailed build notes are in `docs/ENGINE.md` and `engine/assets.sha256`.

Binding bg4 separates native cache entries for money/match units and the depth-dependent cube-efficiency model. Quick/Standard/Deep hints and subsequent move grades reuse one full legal-candidate search, including equivalent move orders. Expert/Research and rollout grades retain separate submitted-move identities because the submitted move affects their shortlist. See `docs/OPTIMIZATION.md` for correctness checks and measured reuse timings.

Quick = 0 ply, Standard = 1 ply, Deep = 2 ply. All use deterministic evaluation, pruning and zero noise; cubeful analysis applies when the cube is enabled. The adapter enumerates **all legal resulting positions** and calls GNUbg `ScoreMove` for every one at the same depth and original cube/match context. This avoids the upstream 40-hint limit and mixed-depth comparisons. A submitted move is validated as a complete legal path, mapped by resulting board, and evaluated identically. Equivalent sequences receive the same grade. Cube analysis passes the actual Jacoby and beaver settings to GNUbg. For immediate redoubles, the adapter enumerates the configured legal response tree, evaluates real post-take positions with GNUbg and their actual cube ownership, and compares every branch in the original player’s perspective and current-cube units. The underlying future-cube model is GNUbg’s beaver-aware approximation, not an exact simulation of all future offers.

Results retain engine revision, settings, request ID, full position key, completion status, computation time, perspective, cubeful and cubeless equity, five nested probabilities and match-winning probability where applicable. Gammon includes backgammon. Money equity uses current-cube units; match equity differences are normalized GNUbg match equity. Main match results show match-winning chance. Small differences are estimates, not certain blunders. Nothing is labeled XG PR. Quick results are completed evaluations; choosing another depth runs another completed calculation. There is no fake streamed result or confidence interval.

New code inside `backgammon/` is GPL-3.0-or-later to keep the combined engine application compatible. This does **not** change the license of unrelated website code. GNUbg and ascottix notices are preserved in the distributed corresponding-source archive. `COPYING.txt`, `licenses/GPL-3.0.txt`, and Settings → Display & controls → About link the license and source. The original site's PeerRoom and hub code retain their existing terms.

## Play, study and persistence

Computer, same-device and private two-player online modes use the same rules/board. Opening rolls reveal a labeled die for each player, explain ties and the winner, and wait for Begin turn before play or computer analysis. Presentation only reveals the committed dice; skipping motion, reloading and reconnecting never rerolls them. Details → All game rules explains movement, dice obligations, scoring, cube rules, resignations and undo, including every active optional rule. Supported sessions: common match lengths through the UI, up to 25 in edited positions, or unlimited points. Doubling, takes, passes, redoubles, gammons/backgammons, resignations, Crawford and post-Crawford are implemented. Default setup is **Unlimited points**, cube enabled, Jacoby on and every opening tie doubling the centered cube: 1 → 2 → 4 → 8, up to the cube limit of 1024. Both players reroll after each tie. Normal in-game doubles give four moves without increasing stakes. Immediate redoubles default to off. Choosing a points match enables Crawford/post-Crawford and disables money-only options. Existing saved games retain their original rules. Setup → Rules exposes cube use, Jacoby, automatic doubling after opening ties (every tie or an explicit lower cap), and beavers or beavers plus raccoons. These money rules are unavailable in matches. Automatic doubles leave the cube centered and do not satisfy Jacoby. A beaver accepts and immediately redoubles while retaining cube ownership; a raccoon is the original doubler’s immediate redouble, with ownership still retained by the beaverer. Passing loses the already accepted stake. Options are fixed for the session, shown in Details, included in history/recovery, and supported by the computer and Solver. See the [backgammon rules glossary](https://bkgm.com/glossary.html) and [GNUbg manual](https://www.gnu.org/software/gnubg/manual/html_node/index.html) for the conventions.

Computer strength maps directly to the documented engine depths. **Hint** appears during your rolled checker turns against GNUbg. It evaluates the whole original roll at the separate hint/review strength, including all legal resulting positions, even if you already have a partial draft. The shared board previews the source and best turn. **Use best move** replaces only the draft; Undo, Reset and Confirm still apply. Close/Escape preserves your draft, and closing a running hint terminates its worker. A failed load offers Retry.

**Show move feedback** can be toggled in setup or in Details / Players during a bot game. After each of **your confirmed checker turns**, a compact strip shows the best evaluated move and estimated loss and remains visible through the bot’s reply. Tap it to compare Position, Best move and Your move. Money games show **EV lost in current-cube points**; match games show **normalized match equity lost**, with the match-winning-chance difference in the review. These are estimates at the selected hint/review strength, not certain blunder classifications. Intermediate checker steps and the bot’s own turns are not graded as new player decisions. The toggle and latest completed feedback survive local resume and Solver round trips; turning it off hides the strip and stops automatic grading. Neither hints nor feedback are offered in online or same-device play.

Forced turns bypass feedback because there is no decision to grade. Feedback uses the actual complete legal turn at the same depth and original player/score/cube context as the alternatives, including moves outside the best few candidates. A turn is locked while being checked; Cancel evaluation restores the draft. Engine failure permits confirmation without feedback. Duplicate confirmations and stale analysis cannot commit another turn. Optional pre-confirmation warnings remain available during setup. Only committed mistakes (loss above 0.020 at the chosen depth) are saved to Trainer with their full original decision and analysis metadata. Computer resignation responses use the engine in money play; in match play it conservatively accepts a guaranteed match win or the maximum three-point multiplier.

Trainer has 34 engine-scored seed positions: 15 openings, six contact, five races, five bearoffs and three public cube fixtures. Non-opening board positions come from legal seeded replay, with the complete generation history stored as provenance. They are **not expert-authored strategic lessons**. Fresh on-device evaluation grades submitted decisions. Answers and rankings remain hidden until submission; hints and skips are separate. Spaced review advances through 1, 2, 4, 7, 14 and 30-day intervals. New users see no invented statistics. Saved mistakes/exercises form a personal practice set.

Solver edits checker placement by explicitly transferring checkers to/from the off trays, or through signed exact point counts. Context has bar/off, dice, side, cube, score, match and Crawford controls. Invalid drafts stay editable and cannot reach WASM. Candidate previews never overwrite the source. Full position links preserve all optional rule and pending-offer context; the verified XGID subset supports standard fields plus Jacoby/beaver flags. Positions can be shared, annotated, saved, made into exercises, or played forward as separate local games. Match review replays application JSON and a strict public text MAT subset, with progressive checker/cube analysis and decision-error navigation.

**Every started local/computer/online session saves automatically** after committed actions in the existing Backgammon IndexedDB, including unfinished games and every game within a match or unlimited session. No cookies or accounts are required. Each online participant keeps their own copy. Existing saved notes/titles survive automatic updates. Play → Details → **All game history** and Library’s **Game history** filter open the archive. **Export → Game history** downloads all stored matches as an importable Library JSON backup; **Export this match** downloads one full match. Older sessions that were never saved cannot be reconstructed.

Library supports search across names/notes/tags, collections, rename, notes, confirmed deletion, per-item exports and validated atomic backup merge/replace. Limits: 8 MB per backup, 2 MB per item, 2,000 imported items. All work is local to this browser; storage can be evicted and is not cross-device backup. Export important work.

## Online assumptions

Unique `backgammon-v1` namespace, two seats, PeerJS 1.5.2 using the site's existing signaling configuration. No accounts/backend. The host validates seat, action, session ID, epoch, expected revision and action ID. Dice are generated only on acceptance and stored in history. Draft moves are local. Duplicates do not reroll; stale/out-of-order actions fail with a message. Snapshot revisions/hashes and a host epoch are application-level metadata independent of transport revisions. The hash detects accidental divergence; it is not a security signature.

After host migration the game pauses. Both original seats must agree on the last checkpoint before resuming. Conflicting histories remain paused rather than being silently merged or rerolled. No future random seed is sent. Reconnect uses the saved identity; duplicate live identities and third players are rejected. Explicit Leave closes the room; this differs from recoverable host disappearance. Saved histories can be exported for manual recovery. Restricted networks may block signaling/WebRTC. This is casual P2P play, not cheat-proof competition. Engine assistance is disabled in online rooms; agreed assisted practice rooms are not yet implemented.

## Offline and updates

Settings shows the installed and published file dates in your local timezone, plus the loaded release ID. **Check for updates** compares the cached page for that release with a fresh `HEAD` response from the published site, bypassing the offline GET handler. Missing dates and offline checks are reported explicitly. These are server file timestamps, not the time you last refreshed. “Up to date” means the published site matches; an unpublished or failed build cannot appear as an available update. **Refresh app** stays visible at the top of Settings, and `/refresh/` redirects to `/backgammon/refresh/`.

`sw.js` is registered by the Backgammon hub and tools and scoped to `/backgammon/`. It uses only `backgammon-assets-*` caches. Shell/data files are installed together; the complete matching engine triplet is cached when engine use first requests it. The hub never starts or preloads the engine. The small shared dependencies are cached only for controlled Backgammon pages. Other families are neither controlled nor purged.

Run `node backgammon/scripts/offline-manifest.mjs` after changing shipped files; commit the generated `offline-manifest.js`, `sw.js` and five entry-point HTML files. The content-derived revision versions the worker's manifest import and each page's entry scripts/styles, changing worker bytes on every release without changing its registration URL. Generated revisions are normalized before hashing, making generation idempotent. This prevents old HTTP-cached imports and decoded stylesheets from hiding releases. Worker registration uses `updateViaCache: "none"`; shell installation uses `cache: "reload"` so a new cache cannot be filled from outdated HTTP-cached scripts or styles. Controlled responses use `Cache-Control: no-store` to prevent a separate browser response cache from bypassing the active release (including WebKit module imports across tool navigation). Explicit CacheStorage still supplies offline files. SHA-256 verification of the complete engine triplet prevents mixing engine/data versions. The deployment test recomputes the release hash, so forgotten generation fails CI.

`ui/updates.mjs` checks on each page load, on returning to a foreground page (network checks throttled to once per minute), and on reconnect. A fully downloaded update activates automatically on a quiet hub or a newly opened tool before any interaction, followed by one reload. A short modal prevents starting an action during activation. The worker validates the caller, deadline and visible client, and refuses early activation while another Backgammon tab or Home Screen window exists. After any tool interaction, updates stay staged for the rest of that page session, including when restored from browser history. Games, draft moves, dialogs and calculations are never intentionally interrupted. A dot on the hub link announces a staged update; return to the hub after finishing and close other Backgammon windows to apply it. The hub explains when another window is holding the update. No periodic background polling or automatic engine loading is used.

Older versions could remain cached because they served the offline shell first, never checked on the hub, and left new workers waiting for every old window to close. An ordinary refresh does not guarantee that those old clients disappear. If that version still hides the new updater, use **Refresh app** on the hub, or open <https://mathewseng.github.io/backgammon/refresh/> once in the affected browser and tap **Refresh Backgammon**, then **Open the updated app**. This standalone, network-only page is also linked from Settings → Display & controls. It downloads a complete fresh shell and activates it after an explicit request and a check that no other Backgammon windows are open. Failed downloads keep the working shell; busy windows receive an actionable message. Neither update path clears IndexedDB, localStorage, or other-family caches. Close other Backgammon tabs and Home Screen windows first; finish online games before refreshing. Saved games, drafts, Library, progress and colors remain available. A recovered first-turn draft also retains its opening acknowledgement when the previous tab has closed.

Offline availability requires successful initial setup and engine caching. The refresh page itself requires a network connection. Multiplayer needs a network. Mobile browsers may suspend workers; completed work is saved, but background analysis after suspension/closure is not promised.

## Exact limits

- Deep/Expert/Research are tree evaluations. Rollouts use the separately documented 0-ply simulation policy and support ordinary cube rules; no beaver/raccoon rollouts. Sampling intervals do not measure model error.
- No immediate redoubles beyond a raccoon, GNU position/match IDs, proprietary binary match imports, or commercial-application parity claim. Automatic opening doubles stop at the cube limit of 1024; new money sessions default to every tie and Jacoby on. Immediate redoubles default off. XGID export rejects context outside the verified subset instead of silently dropping it; use full position links/Library JSON for raccoons, pending immediate offers and opening-double limits.
- MAT import is a tested fixed-column GNUbg/Jellyfish subset. It handles checker moves, bar/off, counts/chains, forced passes, doubles/takes/drops, scores and ordinary win summaries. Edited games, nonstandard columns, special-rule records and ambiguous terminal resignation records fail with a line-specific error. See `docs/FORMATS.md`.
- Match review shows checker and cube losses in normalized equity and filters evaluated errors. Cross-engine performance ratings are not implemented.
- No expert review/classification of advanced tactics such as blitz/backgame/holding/priming is claimed. Only directly supported topic labels are exposed.
- Browser emulation is not real-device testing. See `docs/VALIDATION.md` and `docs/benchmarks.json` for observed coverage and timings.

## Decision history and session review

With **Show move feedback** enabled against GNUbg, confirmed checker moves and cube actions (including rolling instead of doubling) are evaluated in their original context. The scrollable history retains decisions from both players. Row accents and player dots match each side’s checker color, updating with presets and custom colors even after switching sides; player names stay readable and EV-loss values retain their independent blue-to-red scale. Opening rolls, resignations and forced actions are not assigned invented losses. Missing evaluations say **Not analyzed**. **Game review** at the end of a game, or **Review decisions** in Library → **Session Library**, can evaluate unreviewed checker/cube choices at the selected review strength (Deep by default); cancellation retains completed work. Live online Play does not run this analysis.

Every evaluated history row and revealed trainer answer shows a compact Before / Your choice / Best choice equity comparison. Your choice is omitted when it matches the best evaluated equity (within 0.0000001), including equivalent legal moves. Expanded review keeps the EV/match-win details. Values use the decision maker's perspective. Before is the value of the best evaluated continuation with the known decision context, so it equals Best choice; it is not an independently sampled pre-move estimate. Money equity/loss uses the original cube as a unit; the EV column converts to session points. Match-winning probability remains distinct from normalized match equity. Blue marks the best evaluated decision; green/yellow/orange/red are presentation bands at 0.020/0.050/0.100 equity, not uncertainty estimates or a performance rating.

**Undo last turn** always remains at the left of the help controls; it is disabled when no eligible takeback exists. In local Play, reviewed decisions and Session review offer **Return to this position**. This restores the original decision’s dice, board, cube and score, clears the current draft, and keeps the abandoned continuation in the exported history. Reviewing the bot’s decision gives you control of that side so it is immediately playable. Later rolls are fresh, as with other explicit practice edits. Live online games continue to use opponent-approved takebacks and cannot jump through history.

Session Library groups decisions by game and reports each player's evaluated loss and unreviewed count separately. Money totals weight each decision by its original cube; match totals are normalized equity sums. Mixed evaluation strengths are labeled on each decision. Replay-context checks prevent attaching saved grades to a different branch after a takeback. Library backups include these grades; existing unscored games can be reviewed later.

Decision history uses compact rows with explicit **You / Opponent** labels (player names in same-device play), checker-color markers, played moves, aligned Before / Your or Opponent’s choice / Best choice equity, and a separate loss column. Player names, decision type and evaluation preset are secondary text. Units and perspective appear once above the list; each comparison retains accessible unit text. Best-played decisions omit the duplicate played-equity column and duplicate best-move notation. The full comparison and return controls remain available by selecting the row. On narrow screens the same information wraps beneath the identity and loss instead of scrolling sideways.

Play keeps the board and turn controls in the first viewport, with analysis/history below the fold on phones, tablets and desktops. Scroll the page to review decisions; Back to board returns to the playing area. Details remains available as a shortcut drawer. Open board areas allow vertical touch scrolling; movable checker discs retain drag-to-move and pinch zoom. Phone controls retain their compact layout. Feedback never changes board dimensions. Five touching checkers fill each point stack; taller stacks show the total on the innermost checker. Selected checkers have one solid ring; other movable sources are dashed, destination landing rings and die labels remain visible, and keyboard focus has its own outline.

Click a checker disc to select it, then click the open area of a highlighted point or drag to play it. Clicking the same disc again deselects. Point-area clicks prioritize a legal route for the selected checker, even onto a friendly stack; otherwise they play the nearest legal checker. If no checker can land on an owned point, its resident checker is selected instead. Selection alone never moves or undoes a checker. To reverse a moved checker, select it and click its dashed return target, drag it back, or use Undo. **↔ plus a die number** marks a legal alternate first-die landing. Reachable points use a theme-colored wash; amber dashed points are undo destinations. Ambiguous die use opens the route chooser. All routes come from complete legal turns, preserving bar-entry, maximum-dice and bearing-off rules.

The hint dialog also offers **Undo & play best** to replace the draft and commit its best evaluated turn. In a recent human checker review against the bot, the same action rewinds that committed turn and any bot reply before playing the best move. The original line stays in the takeback log, and committed reply dice are reused. The action is unavailable for historical positions, human/online opponents, or turns blocked by the existing forced-turn/cube-boundary takeback policy.

## Keyboard play

Settings → **Keyboard** edits every binding, supports up to three comma-separated aliases or an empty field to disable one action, detects conflicting keys in the same game phase, and can disable game shortcuts entirely. Bindings persist locally. Browser Ctrl/Command/Alt commands, text inputs, key repeats and open dialogs never trigger game shortcuts. Use normal Tab/Shift+Tab, arrows, Enter and Escape inside dialogs (including ambiguous-route choices and opponent takeback approval).

- Top row, left to right: `1 2 3 4 5 6 7 8 9 0 - =`. Bottom row: `Q W E R T Y U I O P [ ]`. These track the displayed orientation. Select a checker, then its destination; Shift + point uses nearest-checker quick play.
- `B`: bar when occupied, otherwise bear off; `A`: bear-off alias; `Z`: undo an unconfirmed draft step only (never a committed turn); `X`: reset draft; `S`: prefer the other remaining die; `Escape`: clear selection.
- `Space` or `Enter`: roll in the rolling/opening phase. `Enter` also confirms a complete turn, acknowledges the opening roll, starts a match or continues to the next game.
- `C`: offer a double before rolling, or beaver/raccoon when answering an offer and permitted. `D` only drops; `T` takes. Untouched older default bindings migrate automatically; customized maps remain yours.
- `H`: hint against the bot; `F`: flip orientation; `?`: keyboard settings/help. Native Tab navigation reaches all other controls. Shortcuts obey the same turn ownership, disabled controls and confirmation policies as pointer input.


Play automatically previews compulsory initial prefixes (such as the only legal bar entry). After a fresh forward choice it may fill an unavoidable continuation, but any roll that originally had different legal outcomes always waits for Confirm. This does not depend on whether a destination was reached by one combined shortcut or several steps. Only the original compulsory prefix is locked; Undo, Reset and reverse moves remain editable and do not immediately refill their removed steps. Reloading or changing settings never commits a chosen draft, including older saved drafts with an automatic-commit flag. Fully forced whole turns/passes remain automatic and host-authoritative online; confirmed chosen turns retain the usual revision/seat checks. Committed dice never change.

Move/cube review uses Board, Comparison and Details views instead of a nested scroll panel. Desktop Comparison shows the full board beside the equity table; phones switch between those views. Explanatory notes are paginated. The cube sits in the right tray gap and follows its owner vertically; Double/Beaver/Raccoon actions use a theme-aware gold treatment. All board dice pips, including ones, use the same radius.

### Practice dice controls

The bottom action bar separates help on the left from decisions on the right. Local and computer tables offer Reroll, Set roll, and separate bot controls. On narrow screens the help row scrolls horizontally while the primary decision remains visible. A practice roll rewinds to that side’s latest roll in the current game, replaces its dice, and resumes play (including automatic forced moves). A side that has not rolled yet has no replacement target. Opening-roll replacements preserve the established first player and cube stakes. Choosing dice pauses the computer until the dialog closes.

These explicit practice edits differ from ordinary Undo, which preserves committed dice. The replaced continuation is retained in the takeback log; `practice-roll` events record replacement dice for deterministic replay, recovery and Library JSON export/import. Online rooms reject practice-roll commands and snapshots. Practice controls do not expose future dice or change an online game.

## Research analysis and live reports

Solver now defaults to completed Quick → Deep refinement and highlights changes in the preferred move. **Roll out this decision** runs real GNUbg simulations in completed 32-trial batches, with 64/256/1024/4096 trials, statistical sampling intervals, cancellation and locally persisted resume. This rollout policy is 0-ply and supports ordinary cube/match play; beavers/raccoons remain tree-analysis only. Sampling intervals exclude policy bias and screening risk. ## Optional board equity bar

**Equity bar** in the toolbar toggles a player-colored rail beside the shared board; it is off by default and the preference persists across tools. In computer Play it runs real GNUbg Quick analysis for the current checker/cube decision, including a complete legal draft. Partial drafts clear the value until complete. Selecting a checker or changing orientation does not recalculate. Online and same-device Play remain unassisted. Trainer waits until submission/reveal, and Solver uses its existing completed analysis; candidate previews hide the bar to avoid labeling a different board with source equity.

The number is signed from the bottom player's perspective: current-cube points in money play, normalized match equity in match play. The visual fill uses the symmetric nonlinear scale `(1 + equity / (1 + abs(equity))) / 2`; it is **not a win probability**. The tooltip identifies units, perspective and settings. Empty/loading/error states never invent equity, and failures offer Retry. Live computer evaluation uses one additional lazy worker with bounded caching; changing the decision cancels active work, and turning the bar off terminates its worker. The board reserves a narrow side lane only while enabled.

### History tree and draft undo

Z (including any remapped Undo shortcut) only removes an unconfirmed draft checker step. It never falls back to Undo last turn, even with an empty draft, after a game, or during the next roll. Committed takebacks remain explicit buttons and retain the existing opponent-consent policy.

**History tree** is available under Play → Analysis & history, Play → Details, Session review, and Library matches. Select any node to preview its board, dice, cube, score and player; browsing leaves the table and draft unchanged. Collapse/expand lines or use arrow keys, Home/End and pagination. Phones have Tree/Board views; desktop can show both. Current position returns the preview to the active line. In local Play, **Return to this position** restores a verified node, preserves its committed dice, and retains the abandoned continuation as another branch. Restoring a bot decision hands that side to the human. Online and Library browsing is read-only.

New takebacks, practice rerolls and history returns save their exact event prefix. Branches survive reload and JSON export/import. Older suffix-only saves attach only when a unique full-state origin exists; ambiguous/unconnected older lines are labeled and previewable but cannot be restored through a guessed ancestry. Equivalent boards reached by different event paths remain separate nodes. Import validation covers branch paths and their analysis metadata as well as the current line.

### Automatic decision analysis

Computer games automatically analyze missing committed decisions for both players, including cube choices and forced turns, even when Show move feedback is off. That toggle controls visible/pre-confirmation feedback, not whether history gets graded. Resuming a game catches up on its missing decisions at the selected Hint & review strength; existing grades retain their recorded settings. Background review shares the existing engine worker, yields to play/hints, pauses when the page is hidden, and saves each completed result to the session Library. Failed analysis shows Retry analysis below the board. Results follow only the same verified history prefix; exploring or replacing a branch cannot attach a stale grade. Online play never starts this automatic assistance.
