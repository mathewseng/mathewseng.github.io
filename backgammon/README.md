# Backgammon

A static, board-first family at <https://mathewseng.github.io/backgammon/>. Real entry points: `play/`, `trainer/`, `solver/`, `library/`. No framework or application build step. Development-only Playwright is pinned in the root package manifest.

## Run and check

```sh
npm ci
node scripts/run-tests.mjs
sh scripts/assemble-site.sh _site
npx playwright install chromium firefox webkit
BG_BROWSERS=chromium,firefox,webkit node backgammon/tests/browser.cjs
# Focused advanced/beginner controls, responsive layouts and real Auto feedback:
BG_BROWSERS=chromium,firefox,webkit npm run test:backgammon:play
# A separate, genuinely live signaling test (serve the repository or _site first):
python3 -m http.server 8765
BG_BASE_URL=http://127.0.0.1:8765 node backgammon/tests/live-network.cjs
BG_BASE_URL=http://127.0.0.1:8765 BG_MONEY_RULES=1 node backgammon/tests/live-network.cjs

node backgammon/scripts/benchmark.cjs
```

Tests explicitly choose Beginner mode when exercising select-then-move controls; other fixtures retain the Advanced default. `tests/play-helpers.cjs` seeds both computer HMAC dice and same-device dice. Opening tests advance the browser clock through each reveal, automatic ties and first-turn start, and check refresh preserves committed rolls. `BG_MODULES=checker-ux,opening-hints` selects focused modules; add `BG_KEEP_GOING=1` to collect independent failures (the command still exits nonzero). Full runs print each module's start and pass status, and include the focused Play controls.

Its artifact test verifies the routes, dependencies, license and engine source archive, and the continued exclusion of blackjack development source. No existing route moved.

## Architecture and controls

The **Openings** tab at `/backgammon/openings/` previews all 15 opening rolls and every published alternative within 0.040 equity of the highest listed value. Choose a move, then **Replies**, to explore all 21 reply rolls. Both stages show move/equity/loss rows, before/after boards and a Solver link. Rankings use the explicitly attributed XG opening book 3.70 (2013): 729 positions and 2,584 candidate values, imported unchanged with source URLs, methods, trial counts and published confidence bounds. XG references use money/Jacoby/beavers-on rules. The page does not change saved game settings. Its Solver link preserves the displayed rule context.

Where XG has no entry or cannot load, the guide uses labeled GNUbg five-ply or rollout estimates with beavers off. XG lists the 5–1 run 24/18 as close but provides no reply page for it; a separately recorded GNUbg five-ply supplement fills all 21 replies. The guide starts no live engine. Live analysis uses XG only for compatible centered-cube money positions with Jacoby and beavers and raccoons on. Other rule contexts use GNUbg, and an unlisted submitted move falls back to a complete GNUbg comparison rather than mixing EV sources. Tests verify all 729 source positions and every imported value in both orientations. Independent GNUbg accuracy experiments remain separate; importing reference values is not a measured gain in engine strength. See [the reference-book method](docs/XG-REFERENCE-BOOK.md).

Rolls use the upper-right triangle of a six-by-six dice grid in both stages, with each combination shown once and the higher die displayed first. The lower-left half stays empty; doubles remain on the diagonal. Opening ties are disabled and labeled **Reroll**. Every playable cell shows the best move’s shorthand and a short description; alternative rows explain points, anchors, hits, splitting, running and builders. Replies default to **White** with a **White / Black** toggle. Changing sides mirrors the legal position, board preview and Solver export, while retaining the same player-relative notation and equity. Tests check all reply combinations in both colors, triangular six-row/six-column geometry, and readable labels down to a 320px viewport.

Roll buttons also list **every close alternative** beneath the best move, in fainter text. The main fill represents the best move’s primary idea, with a labeled color key. The bottom third is divided left-to-right into equal color segments for the alternatives in ranked order; matching dots connect each notation to its category. Mixed moves use their first/main description (hit, anchor, made point, run/split, slot, builder or development). Text wraps independently of the color band so crowded replies remain readable on narrow phones. Tests cover all nine alternatives in the most crowded reply, category colors, contrast and unclipped labels across desktop, portrait and landscape.

**Expanded / Compact** switches between the full-width text grid and a dice-only grid beside the board, retaining the same triangular arrangement and stronger category colors. Compact keeps all 21 targets in a 313px-high block and lists the ranked moves, equities and losses underneath; long desktop lists scroll beside the board. Phone portrait stacks the board, dice grid and moves at full width. The layout preference persists locally, and switching layouts preserves the selected roll, alternative, replying side and Before/After preview without fetching or evaluating again. Browser checks include 1280×800 laptop, 390px phone portrait, phone landscape and 320px narrow layouts.

- `core/table.mjs`: automatic forced turns, committed takeback validation, and replay of previously revealed dice; shared by local and online tables.
- `core/play-session.mjs`: local controller assignments, Play/Solver handoff context and opponent-move markers; no rule-state mutation.
- `core/rules.mjs`: pure state validation, complete-turn enumeration, movement, opening roll, cube, match/Crawford scoring and replay. No random generation inside transitions. Online and same-device dice use cryptographic rejection sampling. Computer tables use a private, cryptographically seeded indexed sequence (`core/local-rolls.mjs`), also with rejection sampling; the seed and cursor survive refresh and takebacks.
- `core/xgid.mjs`: strict standard XGID parsing/serialization. Uppercase is White (GNU player 1); fields include dice, cube, turn, score, match and Crawford. Rejects unsupported flags rather than guessing.
- `core/protocol.mjs` and `play/network.mjs`: host-authoritative protocol over the unchanged `shared/peer-room.js`.
- `ui/board.mjs`, `ui/shell.mjs`, `ui/analysis.mjs`, `styles.css`: one SVG board, shared draft controller, semantic controls, dialogs, settings and analysis display.
- `core/appearance.mjs`, `ui/appearance.mjs`: validated board palettes and the live color editor. One allowlist of color roles drives SVG pieces, move affordances, dice and player markers; game state and engine cache keys are independent of appearance.
- `engine/`: pinned GNUbg, dedicated module worker, full-context adapter and a single-worker priority queue. Worker termination implements actual cancellation. Pending work is rejected; stale UI results are discarded. LRU cache is limited to 64 complete results; queue to 32 jobs. No unbounded persistent evaluation cache.
- `core/storage.mjs`: version-1 IndexedDB for items, recoverable work and spaced-review progress. Small display preferences use `backgammon.v1.*` localStorage. Notes/names are text, never HTML.

Bar entry clears checker selection and shows all remaining legal moves (when hints are enabled), including after combined-dice entries and revisions. Checkers still on the bar retain entry priority. Tap the entered checker again to inspect its continuations or revise its entry die. `tests/bar-entry.cjs` checks the shared behavior across both players, orientations, desktop and touch input.

When bearing off is legal, tapping the free side lane near your off tray bears off using the selected legal die, in either input mode. The cube keeps its own tap target; tapping an orange borne-off checker still returns it. `tests/bearoff-targets.cjs` covers both player directions and orientations, desktop, phone portrait/landscape, die preference, exhausted dice, illegal bearoffs, preview/disabled boards and undo.

White moves from canonical point 24 toward 1; Black the opposite way. `points[0]` is White's point 1, with positive White and negative Black counts. `bar` and `off` are indexed `[White, Black]`. Orientation changes rendering only. `turn` always identifies the original player on roll. `decisionPlayer(state)` identifies the current responder, including alternating beaver/raccoon offers; `pending.depth` is 0 for an ordinary double, 1 for a beaver and 2 for a raccoon. A pending offer doubles the current accepted `cube.value`. `dice` stores the original pair; doubles expand only during move generation. `sequence` increases on committed actions. Match length zero means an unlimited points session. The explicit schema also includes cube ownership, scores, Crawford history, phase, pending offer, game number and result.

In Beginner mode, ringed checkers identify legal sources. Tap/click a source and then a highlighted destination, or drag a checker onto one. Landing rings and destination badges show every reachable distance using one die, both dice, or up to all four dice with doubles. Shortcuts are valid prefixes of complete legal turns; blocked intermediate points cannot be skipped. Combined moves automatically prefer a hitting route, then the selected die when several routes hit. No die-order or route dialog interrupts play. Move through an intermediate point manually to deliberately avoid a hit. Invalid drops cancel without changing the draft; Escape and pointer cancellation also release the checker safely. If both dice can bear off to the same tray, the selected legal die wins. Tap a moved checker and its orange original-position target, or drag it back, to restore its entire journey, dice and any hit checker. Orange targets refer only to its pre-roll origin; intermediate stops and journeys containing a compulsory prefix are excluded. Undo still removes an individual chosen step. Checker revisions show every legal placement using that checker’s own dice plus any unused dice, including partial chains and doubles. For example, both bar/24/20 and bar/21/20 with 1–4 can revise to either 21 or 24; 16/11/8 can revise to 11 or 13. Other checkers’ steps and the original compulsory prefix stay fixed. These legal revisions are highlighted and clickable even before selecting a checker. Unrelated draft steps remain when legal. After a checker enters from the bar (including a multi-die entry or a revised entry), selection clears and all available checker moves reappear. **↔ plus a dice total** marks a revised journey. Tap that target or drag the checker there to revise its placement; the entire draft is replayed to restore dice and hits correctly. The Details move selector offers the same entry change. These shortcuts are only offered when the revised draft remains a prefix of a complete legal turn; blocked entries, maximum dice use and the higher-die rule still apply. If checkers remain on the bar, only legal bar-entry actions are highlighted; ordinary checkers remain unavailable until entry is complete. Strong selection rings, contrasting ring backings and foreground point washes remain visible over board patterns; return targets use one clean outline in the undo color. Undo removes one chosen step; Reset clears the chosen draft steps while keeping a compulsory entry prefix. These controls affect only unconfirmed moves. Large, high-contrast pip dice sit in the board’s central lane; used dice dim and receive a green check for chosen moves or an orange forward arrow for forced moves. Confirm submits a chosen legal turn. A roll with only one legal resulting position plays automatically, including blocked passes and forced bearoffs; equivalent dice orders do not create a choice. When a checker is on the bar and all six entry points are blocked, Play automatically records a real roll and passes without asking for Roll or Confirm. This table convenience skips the optional pre-roll double; pending cube/resignation responses and positions with even one open entry retain their decisions. The host alone advances this in online rooms, and retries/recovery reuse recorded dice. Automatic pre-roll skips are not graded as a player’s cube choice. Forced turns cannot be taken back with ordinary Undo and need no engine evaluation or confirmation. Compulsory prefixes play automatically before a genuine choice; an unavoidable continuation after a chosen step fills the preview, but the whole chosen turn still waits for Confirm. Undo, Reset and checker revisions do not silently refill that continuation. Explicit local practice dice edits can replace even a forced roll. The accessible move selector in Details offers every legal next step. Board controls use one Tab stop, spatial arrow navigation, Enter and Space. Checker moves, hits and undo use short, interruptible motion; opponent moves replay their committed steps and yield immediately to the next action. Reduced motion removes these transitions. Point targets are deliberately distinct; on phones they are **not** 44 pixels wide. The alternative selector provides larger targets. Settings → Display & controls persists point numbering, orientation and motion preference. Browser zoom remains enabled.

In Beginner mode, selecting a checker limits move highlights to its forward routes, alternate first-die moves and undo destinations. A movable checker disc selects (or deselects if already selected), without auto-moving or undoing. An immovable disc passes through to its point’s highlighted destination, if any. Open point space plays a selected legal route; without selection, a previous origin returns its moved checker first, otherwise it uses the nearest legal incoming checker. Otherwise it selects a movable resident or quietly clears selection. No unavailable click changes status text. Repeated point-area clicks can build a point while the arrival remains legal, including doubles. There is no timed double-click mode: fast and slow clicks follow identical rules. After a forward move completes the draft, its reversible landing remains selected so the next tap deselects; bar entries clear selection instead. Shift+point keys explicitly request destination input; ordinary keys retain source selection and the unambiguous undo-only shortcut. Holding a key does not count as repeated presses. The [public controls guide](https://mathewseng.github.io/backgammon/controls/#cases) lists 31 interaction cases alongside click and highlight flowcharts.

## Opening and reply lookup

The [opening guide](https://mathewseng.github.io/backgammon/openings/) includes all 21 distinct rolls, including the six doubles as starting-position studies. All 257 legal starting-double moves are evaluated at 3, 4 and 5 ply; the guide shows the five-ply leader and every alternative within 0.040 at the same depth. There is no shallow candidate filter. This matches the deep GNUbg book’s search method, with Jacoby on and beavers off; it does not claim the same accuracy as the separate published XG rollouts. Starting doubles have no reply branch because actual games reroll tied opening dice. All 21 replies, including doubles, remain available after standard openings. See [generation and validation](docs/OPENING-DOUBLES.md).

Jacoby money games with immediate redoubles disabled first use precomputed rollouts for all 15 openings and 51 selected replies. **Full-game Strong** keeps 2-ply checker and cube decisions throughout: opening 2–1 uses 32,768 trials per retained alternative, and 14 selected replies use 4,096. The other 51 decisions retain 512-trial Short/deep estimates. Results retain their samples, standard errors and recorded policy. The independent full-game cohort lowered the sampled mean move-gap difference from XG by 34% and confirmed an average cutoff effect; all 15 entries qualified together under recorded criteria. Opening 2–1 resolves in favor of slotting, while individual reply preferences remain uncertain. This targeted comparison does not establish general playing strength. See [the full-game results and reproduction](docs/FULLGAME-PRECISION.md) and [the earlier rollout comparison](docs/ROLLOUT-POLICIES.md).

The **5-ply opening and reply book** remains the fallback. It evaluates every legal opening move; every covered close opening has all 21 reply rolls, with alternatives screened at three/four plies before a consistent five-ply comparison. An unlisted rollout move is graded using one complete fallback comparison, never by subtracting scores from different methods. [Five-ply methodology and external XG comparison](docs/DEEP-OPENING-BOOK.md) document its coverage and remaining differences.

The historical **3-ply** book remains available for download fallback and later turns: 1,298 third-turn boards (27,258 decisions) and 32 selected fourth-turn boards, with partial fourth-turn coverage. Both players, dice orders and centered cubes raised by opening ties are supported. The books are shared across bot play, hints, grading, Trainer and Solver. Results identify their actual method, depth and sampling uncertainty, overriding Quick through Expert and Auto only where covered. Research, rollouts, other rules/match contexts, and unlisted submitted replies use live GNUbg. Previously downloaded tables work offline. See [historical coverage, generation and tests](docs/OPENING-BOOK.md).

The historical five-ply comparison covers all 15 openings and 651 reply positions in XG. Mean EV difference on XG's preferred moves changes from 0.00839 to 0.00751 for openings and 0.01898 to 0.01213 for replies. Best-move agreement is not monotonic with depth; the [report](https://mathewseng.github.io/backgammon/reports/#opening-accuracy) shows three, four and five plies side by side. Validation for this release: 494 repository tests, 16 final deployment/offline/manifest checks, and focused guide/book browser checks in Chromium, Firefox and WebKit. Full methodology, recorded outputs and limitations are in [DEEP-OPENING-BOOK.md](docs/DEEP-OPENING-BOOK.md).

## Engine, evaluation and licensing

Upstream: <https://github.com/ascottix/gnubg-core>, pinned to `955555c69adebb1d7de23abc1018074158621168`, web binding **bg8**. Distributed loader/WASM/data are built with **Emscripten 4.0.15**: scalar `-O2` and optional SIMD `-O3 -flto -msimd128 -ffp-contract=off`, no pthreads. Cross-origin isolation is unnecessary. The data archive contains neural weights, bearoff databases and Kazaross-XG2 match-equity data. Asset checksums and detailed build notes are in `docs/ENGINE.md` and `engine/assets.sha256`.

Binding bg6 automatically selects supported SIMD acceleration, falls back to scalar if loading fails, and shares one neural/bearoff/MET data package. Both executables retain the same weights and search settings. bg6 adds indexed duplicate-move detection and further SIMD neural calculations, with a tested allocation fallback. The precomputed book retains its original bg5 provenance. See `docs/BG6-RELEASE.md` for measurements and release checks. Backend identity is included in saved evaluation metadata. Binding bg4, retained in bg6, separates native cache entries for money/match units and the depth-dependent cube-efficiency model. Quick/Standard/Deep hints and subsequent move grades reuse one full legal-candidate search, including equivalent move orders. Expert/Research can reuse a completed same-depth hint when it includes the submitted move; otherwise the submitted move is explicitly added to a new search. Auto and rollout grades keep their separate submitted-move identities. See `docs/OPTIMIZATION.md` for correctness checks and measured reuse timings.

Quick = 0 ply, Standard = 1 ply, Deep = 2 ply. All use deterministic evaluation, pruning and zero noise; cubeful analysis applies when the cube is enabled. The adapter enumerates **all legal resulting positions** and calls GNUbg `ScoreMove` for every one at the same depth and original cube/match context. This avoids the upstream 40-hint limit and mixed-depth comparisons. A submitted move is validated as a complete legal path, mapped by resulting board, and evaluated identically. Equivalent sequences receive the same grade. Cube analysis passes the actual Jacoby and beaver settings to GNUbg. For immediate redoubles, the adapter enumerates the configured legal response tree, evaluates real post-take positions with GNUbg and their actual cube ownership, and compares every branch in the original player’s perspective and current-cube units. The underlying future-cube model is GNUbg’s beaver-aware approximation, not an exact simulation of all future offers.

Results retain engine revision, settings, request ID, full position key, completion status, computation time, perspective, cubeful and cubeless equity, five nested probabilities and match-winning probability where applicable. Gammon includes backgammon. Money equity uses current-cube units; match equity differences are normalized GNUbg match equity. Main match results show match-winning chance. Small differences are estimates, not certain blunders. Nothing is labeled XG PR. Quick results are completed evaluations; choosing another depth runs another completed calculation. There is no fake streamed result or confidence interval.

New code inside `backgammon/` is GPL-3.0-or-later to keep the combined engine application compatible. This does **not** change the license of unrelated website code. GNUbg and ascottix notices are preserved in the distributed corresponding-source archive. `COPYING.txt`, `licenses/GPL-3.0.txt`, and Settings → Display & controls → About link the license and source. The original site's PeerRoom and hub code retain their existing terms.

## Play, study and persistence

Computer, same-device and private two-player online modes use the same rules/board. Opening rolls reveal a labeled die for each player, explain ties and the winner, and automatically begin the winning turn after a readable result hold. Presentation only reveals the committed dice; skipping motion, reloading and reconnecting never rerolls them. Details → All game rules explains movement, dice obligations, scoring, cube rules, resignations and undo, including every active optional rule. Supported sessions: common match lengths through the UI, up to 25 in edited positions, or unlimited points. Doubling, takes, passes, redoubles, gammons/backgammons, resignations, Crawford and post-Crawford are implemented. Default setup is **Unlimited points**, cube enabled, Jacoby on and every opening tie doubling the centered cube: 1 → 2 → 4 → 8, with no tie-count cap (a numeric safety bound of 2²⁹ prevents overflow). Both players reroll after each tie. Normal in-game doubles give four moves without increasing stakes. Beavers and raccoons default to on in unlimited sessions. Choosing a points match enables Crawford/post-Crawford and disables money-only options. Existing saved games retain their original rules. Setup → Rules exposes cube use, Jacoby, automatic doubling after opening ties (every tie or an explicit lower cap), and beavers or beavers plus raccoons. These money rules are unavailable in matches. Automatic doubles leave the cube centered and do not satisfy Jacoby. A beaver accepts and immediately redoubles while retaining cube ownership; a raccoon is the original doubler’s immediate redouble, with ownership still retained by the beaverer. Passing loses the already accepted stake. Options are fixed for the session, shown in Details, included in history/recovery, and supported by the computer and Solver. See the [backgammon rules glossary](https://bkgm.com/glossary.html) and [GNUbg manual](https://www.gnu.org/software/gnubg/manual/html_node/index.html) for the conventions.

Computer strength maps directly to the documented engine depths. **Hint** appears during your rolled checker turns against GNUbg. It evaluates the whole original roll at the separate hint/review strength, including all legal resulting positions, even if you already have a partial draft. The shared board previews the source and best turn. **Use best move** replaces only the draft; Undo, Reset and Confirm still apply. Close/Escape preserves your draft, and closing a running hint terminates its worker. A failed load offers Retry.

**Show move feedback** can be toggled in setup or in Details / Players during a bot game. After each of **your confirmed checker turns**, a compact strip shows the best evaluated move and estimated loss and remains visible through the bot’s reply. Tap it to compare Position, Best move and Your move. Money games show **EV lost in current-cube points**; match games show **normalized match equity lost**, with the match-winning-chance difference in the review. Neither hints nor feedback are offered in online or same-device play.

Forced turns bypass feedback because there is no decision to grade. Fresh on-device evaluation grades submitted decisions. Answers and rankings remain hidden until submission; hints and skips are separate. Spaced review advances through 1, 2, 4, 7, 14 and 30-day intervals. New users see no invented statistics. Saved mistakes/exercises form a personal practice set.

**Every started local/computer/online session saves automatically** after committed actions in the existing Backgammon IndexedDB, including unfinished games and every game within a match or unlimited session. ## Online assumptions

Unique `backgammon-v1` namespace, two seats, PeerJS 1.5.2 using the site's existing signaling configuration. No accounts/backend. The host validates seat, action, session ID, epoch, expected revision and action ID. Dice are generated only on acceptance and stored in history. Draft moves are local. Duplicates do not reroll; stale/out-of-order actions fail with a message. Snapshot revisions/hashes and a host epoch are application-level metadata independent of transport revisions. The hash detects accidental divergence; it is not a security signature.

After host migration the game pauses. Both original seats must agree on the last checkpoint before resuming. Conflicting histories remain paused rather than being silently merged or rerolled. No future random seed is sent. Reconnect uses the saved identity; duplicate live identities and third players are rejected. Explicit Leave closes the room; this differs from recoverable host disappearance. Saved histories can be exported for manual recovery. Restricted networks may block signaling/WebRTC. This is casual P2P play, not cheat-proof competition. Engine assistance is disabled in online rooms; agreed assisted practice rooms are not yet implemented.

## Offline and updates

Settings shows the installed and published file dates in your local timezone, plus the loaded release ID. **Check for updates** compares the cached page for that release with a fresh `HEAD` response from the published site, bypassing the offline GET handler. Missing dates and offline checks are reported explicitly. These are server file timestamps, not the time you last refreshed. “Up to date” means the published site matches; an unpublished or failed build cannot appear as an available update. **Refresh app** stays visible at the top of Settings, and `/refresh/` redirects to `/backgammon/refresh/`.

`sw.js` is registered by the Backgammon hub and tools and scoped to `/backgammon/`. It uses only `backgammon-assets-*` caches. Shell/data files are installed together; the complete matching engine triplet is cached when engine use first requests it. The hub never starts or preloads the engine. The small shared dependencies are cached only for controlled Backgammon pages. Other families are neither controlled nor purged.

Run `node backgammon/scripts/offline-manifest.mjs` after changing shipped files; commit the generated `offline-manifest.js`, `sw.js` and family entry-point HTML files. The content-derived revision versions the worker's manifest import and each page's entry scripts/styles, changing worker bytes on every release without changing its registration URL. Generated revisions are normalized before hashing, making generation idempotent. This prevents old HTTP-cached imports and decoded stylesheets from hiding releases. Worker registration uses `updateViaCache: "none"`; shell installation uses `cache: "reload"` so a new cache cannot be filled from outdated HTTP-cached scripts or styles. Controlled responses use `Cache-Control: no-store` to prevent a separate browser response cache from bypassing the active release (including WebKit module imports across tool navigation). Explicit CacheStorage still supplies offline files. SHA-256 verification of the complete engine triplet prevents mixing engine/data versions. The deployment test recomputes the release hash, so forgotten generation fails CI.

`ui/updates.mjs` checks on every page load before a tool initializes. A confirmed new release is mandatory: a blocking screen counts fully downloaded shell files, activates the complete release and reloads once. It never invents a percentage or downloads the engine just to show progress. A failed download or another open Backgammon tab keeps the gate closed. It retries automatically after 1, 3 and 10 seconds, then leaves an actionable Retry button; reconnect/foreground events can check again. Checks have deadlines so a stalled browser update job cannot permanently disable Retry. The gate asks the active worker for its release ID: if activation already finished while the document still has old HTML, it reloads the installed release instead of waiting for a nonexistent installation. A per-tab guard prevents repeated stale-document reloads. Other live Backgammon windows still prevent activation so their work is not interrupted. An unconfirmed/offline check allows cached local tools; an eight-second network-check timeout avoids a blank page. Foreground/reconnect checks may stage a release during play; that release installs on the next page load rather than interrupting a live decision.

`node --test backgammon/tests/update-gate.test.mjs backgammon/tests/offline.test.mjs` covers lifecycle races, stalled checks, retry limits and release probes. Shared links to a different position do not restore an unrelated checkpoint. Online play keeps its existing validated room recovery/reconnect flow; a local checkpoint never becomes multiplayer authority. A restored browser-history page reloads through the same gate. Updates never clear game storage or other families' caches.

Move arrows use a tangent graph around 44px clearance discs: twice the 22px checker radius, leaving one checker radius outside each disc. Most bends are circular arcs; short degree-seven Hermite transitions match position and three derivatives at line/arc joins, rendered with a subpixel cubic approximation. Smooth curvature/jerk **continuity** is not literal zero jerk along a curved path. Closed-off clusters use the existing checker/dice mask rather than painting through faces. Ghost, movable and last-moved circles use normalized circumferences with evenly dividing dash/gap periods and rounded caps, so the seam has no leftover dash.

## Exact limits

- Deep/Expert/Research are tree evaluations. Rollouts use the separately documented 0-ply simulation policy and support ordinary cube rules; no beaver/raccoon rollouts. Sampling intervals do not measure model error.
- No immediate redoubles beyond a raccoon, GNU position/match IDs, proprietary binary match imports, or commercial-application parity claim. Automatic opening doubles stop at the cube limit of 1024; new money sessions default to every tie and Jacoby on. Immediate redoubles default off. XGID export rejects context outside the verified subset instead of silently dropping it; use full position links/Library JSON for raccoons, pending immediate offers and opening-double limits.
- MAT import is a tested fixed-column GNUbg/Jellyfish subset. It handles checker moves, bar/off, counts/chains, forced passes, doubles/takes/drops, scores and ordinary win summaries. Edited games, nonstandard columns, special-rule records and ambiguous terminal resignation records fail with a line-specific error. See `docs/FORMATS.md`.
- Match review shows checker and cube losses in normalized equity and filters evaluated errors. Cross-engine performance ratings are not implemented.
- No expert review/classification of advanced tactics such as blitz/backgame/holding/priming is claimed. Only directly supported topic labels are exposed.
- Browser emulation is not real-device testing. See `docs/VALIDATION.md` and `docs/benchmarks.json` for observed coverage and timings.

## Research analysis and live reports

Solver defaults to **Auto · 2 ply minimum**. It always finishes at least two plies, normally attempts three, and may reach four. It skips a deeper stage only when its estimated cost exceeds five seconds or the leading move has a substantial, stable equity advantage. The old one-second deadline is removed: time spent reaching two ply does not reduce the allowance for the next stage, and actual time can exceed the estimate. Cancel remains available; engine failures/timeouts reject rather than return a shallow final result. See [adaptive search evidence and policy](docs/SEARCH-POLICY.md) for thresholds, safeguards and measured scope. Auto uses a broad 0-ply screen (top 16, up to 24 within 0.160 equity, plus the submitted move) before 1/2-ply search. Expert (3 ply) and Research (4 ply) narrow the 2-ply list further. Every compared move is evaluated at the same displayed depth; screened-out moves can still be better. Fixed Quick/Standard/Deep remain exhaustive over legal results. Depth, filtering and completion metadata are saved with results. Play's **Hint & review strength** is independent of computer strength and also defaults to Auto. ### Certain bearoff results

Play automatically finishes a contact-free race between turns or after rolling when the same winner and scoring level are guaranteed under **every remaining roll and every legal move**, including deliberately poor play. For a known roll, it checks every legal outcome before proving the remaining race; the actual dice reveal completes before awarding the result, without inconsequential checker animations. It compares the winner's worst-case remaining turns with the loser's fastest possible finish and first bearoff, accounting for who rolls next. Small home-board searches enumerate all legal outcomes; safe pip/count bounds avoid most enumeration. A deterministic work cap leaves unproved positions live. Engine equity, rounded scores and future seeded rolls never establish certainty, and uncertain backgammon-risk positions remain live.

The normal cube, Jacoby and match-target scoring apply once through a replayable `finish-race` event. No dice or checker moves are invented. The host applies the same proof online; command retries and recovery retain the result. Undo turn reopens the decision for review without immediately finishing again.
