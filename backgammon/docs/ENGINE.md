# Engine distribution

Source: <https://github.com/ascottix/gnubg-core/tree/955555c69adebb1d7de23abc1018074158621168>. GPL-3.0-or-later. Upstream authors include Gary Wong, GNUbg contributors, and Alessandro Scotti; their file notices are retained. New `bridge.c` is GPL-3.0-or-later.

## Rebuild

Install and activate Emscripten **4.0.15** (emsdk resolves it to `b412b6307e541b93dd93f01b61181e15c17302ec`). Then from the repository root:

```sh
sh backgammon/scripts/build-engine.sh
node backgammon/scripts/offline-manifest.mjs
sh scripts/assemble-site.sh _site
node backgammon/tests/browser.cjs
```

`build-engine.sh` downloads the exact revision, copies `engine/source/bridge.c`, runs `patch-engine.py`, compiles both executables, and creates the bg8 corresponding-source archive. It rejects unpinned compiler versions. The distributed archive also builds directly with `make -f Makefile.emcc` (scalar) and `make -f Makefile.emcc VARIANT=simd` (SIMD); it includes the patched Makefile, all C source, original web glue, weights, MET and bearoff assets. The scalar fallback retains `-O2`; the SIMD variant uses `-O3 -flto -msimd128 -ffp-contract=off`. Both use 64 MiB initial WASM memory with growth and a 1 MiB stack. The build compares the two data packages byte-for-byte and ships only one shared package. The source archive is available from the application's About view. Source ordering is explicit and the archive has normalized timestamps/ownership and no macOS metadata files. For bg6, a clean extraction/rebuild reproduced both loaders, both WASM executables, the shared data and the source archive byte-for-byte with the pinned toolchain. Set `BG_ENGINE_OUTPUT=/absolute/staging/engine` to build outside the deployed asset directory.

## Binding changes

Current binding **bg8** fixes cubeful cache reuse across incompatible checker-policy cube contexts. A counterfactual cube branch shares checker decisions made for the original policy cube; its value therefore depends on both contexts. Money keys now retain the policy cube, owner, turn, Jacoby and beaver settings. Match positions skip incompatible counterfactual cache entries when their full contexts differ. A deterministic regression reproduced 20 wrong cache hits under ordinary cube rules across both 41$-44 continuations, with errors up to 0.00228506; all captured queries match fresh evaluation after the patch. This verifies the defect and repair, not the size of its full-game EV effect. The fixed independent experiment measures that effect separately from cube-rule and checker-strength changes.

The only source member changed from the bg7 archive is `src/eval.c`, through `engine/source/checker-context-bg8.patch`. Neural weights, databases, search depths and rollout policies are unchanged. Scalar and SIMD use the same correction. The live engine version changes to invalidate incompatible result caches and rollout checkpoints; historical book values retain their original source versions. [Release hashes](bg8-release.json), [production regression](live-cache-context-validation.json) and [controlled experiment](CUBE-POLICY-STUDY.md) provide the evidence. The research runtime's expanded cube policies remain separate from browser rollout support.

Binding **bg7** added explicit Basic (0/0), Balanced (1/1) and Strong (2/2) checker/cube policies to native full-game rollouts, plus Short/deep (initial 2/2, later 1/2 after two turns, truncated after five turns with a two-ply endpoint). Both players use the selected policy; each batch resets the search depths and normal move filters. The legacy four-argument rollout export remains Basic. Policy metadata is checked at the JS boundary and is part of checkpoint identity. The rollout settings do not change the neural weights. See [ROLLOUT-POLICIES.md](ROLLOUT-POLICIES.md) for implementation checks and the independent XG comparison.

The bg7 patch also repairs `CompareMoves`: equal primary and secondary scores previously returned −1 in both comparison directions, violating the C sort contract. Equal scores now use a deterministic position-key order, with zero returned for identical keys. This fixes a reproduced native/WASM seeded-rollout probability discrepancy in a match where backgammons have no additional value. The patch is `engine/source/rollout-order-bg7.patch`.

Binding **bg6** extends SIMD to four independent hidden activations and output neurons, using the original sigmoid approximation and each neuron's original accumulation order. A packed copy of the output weights adds about 6.6 KiB. Failure of that optional allocation falls back to the original output loop without changing results. Original weights remain available for binary save/load; destruction releases the packed copy. A 64 KiB index replaces the duplicate-move linear scan with full-key collision checks, retaining insertion order and the first legal path. Generation epochs reset on each roll and when maximum-dice filtering replaces the list, including wraparound. The move index applies to both builds; activation/output SIMD applies only to the SIMD build. These changes are in `engine/source/native-search-bg6.patch`. Weights, search depths, filters, match tables and rollout policy are unchanged. See [BG6-RELEASE.md](BG6-RELEASE.md) for exact-build measurements, differential checks and release provenance.

Binding **bg5** added standard WebAssembly SIMD in the neural-network hidden layer. Four independent hidden neurons are processed at once; each neuron retains its input accumulation order and the output reduction remains unchanged. No fast-math, relaxed SIMD or threads are enabled. The patch is `engine/source/neuralnet-simd.patch`; the scalar preprocessor branch remains the original implementation. The weights, bearoff tables and search presets are unchanged.

Binding **bg4** fixes two native evaluation-cache collisions; bg6 retains both corrections. `EvalKey` now uses bit 29 to distinguish match play from money play (double-match-point has zero away-score bits), and bit 28 to distinguish the cube-efficiency model selected by a root depth of at least two plies. The previous key recorded remaining depth but omitted the root-depth model used by `EvalEfficiency`. These changes preserve neural weights and search depth while preventing results from a different calculation context being reused. Regression tests compare mixed-context warm-worker results with fresh-worker results.

Binding **bg3** added the four-ply depth bound and `bg_rollout(original, after, trials, seed)`; bg6 retains those capabilities. Checker batches use `ScoreMoveRollout`; cube batches use `GeneralCubeDecisionR`. The bg6 corresponding-source archive includes the full modified engine and both build variants; earlier archives remain available for their historical releases. The reproducible `patch-engine.py` also removes diagnostic rollout spam, implements the RNG setter for valid seeded calls and uses a no-op event hook; the JS worker yields between completed batches. The RNG and simulation policy are initialized explicitly on every batch. No pthreads or deployment headers are required.


- Export `bg_score(originalXgid, afterXgid, plies, beavers)`, `bg_cube(xgid, plies, beavers)` and `bg_value(xgid, plies, beavers)` as allocated JSON. The JS adapter always frees returned buffers. Keep original `hint` exported for independent binding regression comparisons.
- Web binding **bg2** passes the actual beaver flag to GNUbg; Jacoby comes from XGID’s rule bit. The original `hint` binding keeps beavers off for comparison with standard fixtures. All deployed optional rules are also represented in the full application cache key.
- Use `PositionKey` on the after-position, then **ScoreMove** with the original cube/match context. GNUbg performs opponent evaluation, probability inversion, and conversion back to the original player's equity. The adapter does not manually negate an incompatible post-roll evaluation.
- Return eight-decimal cubeful/cubeless values, the five GNUbg probabilities, and `eq2mwc` conversion for matches. Win-gammon/loss-gammon include backgammons.
- `turn` stays the original roller throughout the cube chain. `pending.by` identifies the offerer, so `decisionPlayer` alternates correctly for beavers and raccoons. Response losses compare from that actor’s perspective without reversing the board.
- With immediate redoubles enabled, enumerate every permitted take/pass/beaver/raccoon branch through the same pure game transitions used by Play. `bg_value` calls **GeneralEvaluationE** on the actual accepted-cube position. Multiply by the accepted cube divided by the original decision cube; compare max for the original roller and min for the opponent. Pass values come from the real scoring transition. The current response chain is explicit; future cube ownership/equity uses GNUbg’s beaver-aware approximation. This is not a rollout or exact solution.
- No-cube positions use cubeless evaluation and report `settings.cubeful: false`.

The upstream public hint list caps at 40. Our application enumerates complete legal turns, deduplicates resulting boards, and evaluates all of them at one depth for Quick/Standard/Deep. Expert/Research then rescore screened finalists (including every submitted move) at 3/4 ply, with the screening limit shown. A browser regression checks a 75-result doubles position and grades an actual move strictly below the worst returned upstream hint. It also compares five opening evaluations against the original C hint API, within 0.00011 (the original API rounds to four decimals). Other regression checks cover public cube fixtures, mirror/player perspective, and different match scores.

Checker Research adds policy `retain-expert-leader-v1`: its original 2-ply shortlist is preserved, plus the default Expert shortlist's 3-ply winner. Every finalist is then evaluated at 4 ply. The adapter holds at most 32 candidate scores **at each of 3 and 4 ply**, each depth restricted to one full context and exact root-candidate set, with cloned values and FIFO eviction. This avoids repeating Expert's native calculation during progressive search and Research's completed finalist scores when grading an additional submitted move. No three-ply call is needed if every possible Expert leader is already a Research finalist. `screening.retainedLeader` records whether a finalist was added, and `settings.screeningPolicy` distinguishes this behavior from saved historical Research results. The native binding remains bg6; no weights, native filters or opening-book inputs changed. See [RESEARCH-SCREEN.md](RESEARCH-SCREEN.md) for the defect and cold/progressive timing tradeoff, and [FINALIST-CACHE.md](FINALIST-CACHE.md) for arbitrary-move grading measurements and isolation tests.

## Opening book

The default `PreferredOpeningBook` uses the explicitly attributed [published XG reference book](XG-REFERENCE-BOOK.md) for compatible centered-cube money positions with Jacoby, beavers and raccoons enabled. It contains 729 decisions and 2,584 published candidate values. An unlisted submitted move falls back to a complete GNUbg comparison, without mixing the two sources. These imported values remain separate from independent engine experiments; the bg8 cache fix does not relabel or replace them.

Jacoby money openings and replies with immediate redoubles disabled first use the separately identified **bg7-native rollout book**, `jacoby-rollout-v2`: all 15 openings and 51 selected replies. Opening 2–1 uses 32,768-trial Full-game Strong estimates, and 14 replies use 4,096-trial Full-game Strong estimates; the other 51 entries retain 512-trial Short/deep estimates. Strong keeps checker and cube decisions at 2-ply with no turn cutoff. Each entry carries its policy, samples and standard errors. The fallback `RolloutOpeningBook` wraps the historical lookup: other opening/reply decisions retain the **bg6-native five-ply book**, then the **bg5 three-ply book** supplies download fallback and later turns. Historical values retain their recorded engine version. Unlisted submitted moves receive a complete comparison at the fallback method, without mixing equities. Other rules/match contexts, Research and explicitly requested live rollouts use the worker. [Full-game validation](FULLGAME-PRECISION.md), [rollout methodology](ROLLOUT-POLICIES.md), [five-ply coverage](DEEP-OPENING-BOOK.md) and [historical coverage](OPENING-BOOK.md) document the separate sources.

## Worker and capabilities

The engine runs in one dedicated module Worker; the WASM itself is single-threaded. `engine/backend.mjs` validates a small SIMD module before selecting an executable. Supporting browsers load `vendor/simd/`; other browsers load the scalar `vendor/` executable. A failed SIMD download, compile or initialization retries the scalar engine using the same data package. If both builds or the data package fail, loading rejects with a retryable error. `?backend=scalar` on the worker URL forces the fallback for reproducible comparisons. Startup metadata and completed results record the backend, while the versioned native cache identity is bg8. Cross-backend seeded-rollout resume is tested. The optional executable is about 202 KB WASM plus 67 KB loader; it does not duplicate the 9.8 MB neural/bearoff/MET package. Asset transfer, compilation, initialization and computation are timed separately. Failures remaining after fallback, worker crashes and timeouts reject pending promises. Cancel terminates the worker, frees its WASM address space, and invalidates its generation. A later request creates a fresh worker. Posting a cancel message alone would not interrupt synchronous WASM and is deliberately not used.

Quick/Standard/Deep checker requests share their full-candidate result regardless of which legal move a caller submits. The client validates the submitted complete turn and returns a caller-specific grade without mutating the cached hint. Expert/Research can also grade a move already present in a completed hint at the same fixed depth, including when that hint finishes while the grade is queued. A foreground grade promotes its matching in-flight hint instead of cancelling it. An omitted move still requires a new search with that move explicitly included. Auto and rollouts retain separate submitted-move identities: Auto grading must not inherit a hint's clear-lead early stop. All reuse is keyed by the complete original position, dice, player, cube, match/rules context and preset. Cached objects are isolated from editable returned results, including nested candidates, probabilities and screening metadata.

A foreground duplicate promotes an already queued background job; duplicate rollout subscribers receive the same completed checkpoints. Late errors from terminated workers are ignored, and worker creation/send failures leave a retryable client. Cache and queue bounds remain 64 results/32 jobs. `scripts/screened-reuse-benchmark.cjs` compares this fixed-depth grading shortcut with client revision `62f0259`, using identical assembled native assets and disabled opening-book lookup; see [SCREENED-REUSE.md](SCREENED-REUSE.md).

Queued requests snapshot submitted checker moves and rollout options, including nested resume data, as well as the position. Editing a UI draft while the worker loads or processes another job cannot change the calculation behind an existing cache key. See [native search experiments and request isolation](NATIVE-SEARCH-PILOTS.md) for the regression and the experiments that preceded the bg6 release. The rejected cache, tiling and pruning-state experiments remain undeployed.

Solver's default `auto` is a progressively deepened sequence of completed 0/1/2/3/4-ply evaluations, not a new neural network or a rollout. `engine/adaptive.mjs` declares a mandatory two-ply minimum, a five-second estimated next-stage limit and the root filter. Automatic 1/2-ply search keeps the top 16 zero-ply candidates, up to 24 within 0.160 equity, and any submitted legal move. Automatic 3/4-ply searches apply the existing Expert/Research filters to that list, retaining the preceding winner and any submitted move. Policy `minimum-two-v2` always finishes 2 ply, normally tries 3, and may reach 4. At 2/3 ply it can stop after a stable, clear lead (outside match/actual-move grading), or skip a next stage forecast above 5,000 ms. This limit is per next stage, not total elapsed time. Cube estimates extrapolate observed stage growth; they do not use the checker timing regression or gap shortcut. Its small empirical timing model scales with observed per-candidate performance; it is not a guaranteed ETA. Auto settings/cache identity include the policy version. See [SEARCH-POLICY.md](SEARCH-POLICY.md) for evidence, thresholds, limitations and reproduction. Fixed 0/1/2-ply presets still score every legal result. The adapter retains only one zero-ply and one two-ply root list, keyed by full position/match/rules context and the exact screened candidate keys. It clones cached values so result previews/annotations cannot corrupt later scoring. This avoids repeating root screening when deepening, without comparing scores from different depths.

The worker sends genuine completed evaluations via `onEvaluation`. Intermediate 0/1-ply results never resolve Auto; the parent also rejects a malformed final Auto response below 2 ply instead of caching it. No one-second or five-second wall timer interrupts an otherwise eligible stage. Explicit cancellation terminates synchronous WASM and rejects with `AbortError`, including after completed updates. The existing five-minute job watchdog rejects an unresponsive/exceptionally slow job rather than presenting a shallow result as completed Auto. Generation checks reject stale messages, and a later request initializes a fresh worker. `result.settings.plies` identifies the actual completed depth; settings record policy, minimum and cost limit. `settings.rootFilter` and `screening.initial` record screening, while `budget` records completed levels, stop reason, lead and forecast. Screened-out alternatives remain a limitation, and fixed-depth controls are available.

Capabilities are explicit in `engine/metadata.mjs`: checker analysis, legal arbitrary-move grading, cube and match contexts, Jacoby, automatic opening stakes, beavers and raccoons, and 0–4 ply. Binding **bg3** adds real GNUbg rollouts for ordinary cube/match rules, independent 32-trial batches, resumable sample moments, and sampling intervals. See `RESEARCH.md` for policy, seeding, uncertainty, candidate screening and limits. Beavers/raccoons remain tree-only. The worker serializes the core’s global rollout context and yields between batches; cancellation terminates it.

## Verification and timing

`tests/backend-loading.cjs` uses a real local HTTP fixture to test ten automatic/forced backend, missing/invalid asset, initialization-error, failure and retry cases across Chromium, Firefox and WebKit. Capability failure is simulated; the selected scalar or SIMD engine is real WASM. `tests/native-backends.cjs` compares all 34 authored fixtures at Quick/Standard/Deep, extra money/match/owned-cube/player contexts, 3/4-ply samples, arbitrary-move grading, seeded rollouts and checkpoint resume. Chromium also compares all 300 historical reference positions at Deep. It checks complete candidate coverage, best decision, probabilities, cube outcomes and numerical agreement within 0.00001. This is implementation parity evidence, not proof of stronger play. With `_site` served, `BG_BASE_URL=http://127.0.0.1:8878 node backgammon/scripts/validate-backends.cjs` reproduces the three-browser run and writes `docs/backend-validation.json`.

`node backgammon/scripts/native-benchmark.cjs` records five alternating paired workers per position and preset for scalar and SIMD builds. Each worker records its first search and three warm repeats. Run without concurrent heavy work. Output is `data/native-benchmark.json`, shown on the public engine report. It includes raw samples, engine/build/asset identities, canonical positions and settings, startup components, and median/range summaries. This measures local desktop HTTP, not a phone or Internet connection.

`tests/browser.cjs` loads the deployed JS/WASM/data from the assembled site without cross-origin-isolation headers. `scripts/benchmark.cjs` separates fresh-worker cold computation from repeated evaluations with warm GNUbg internal caches. Warm and cold timings must not be conflated. `docs/benchmarks.json` contains every sample; cold n=5 and startup n=10 report ranges, not a p95. Warm n=30 has p95. This is local HTTP on an Apple M4 Pro, not mobile hardware or an Internet transfer benchmark.

`tests/options-ui.cjs` checks a legally constructible race (15 Ivory on its 6 point, 15 Teal on its 4 point), deliberately doubled by the trailing roller. Quick/bg2 take equity is −1.80594110 current-cube points (tolerance 0.00002); the optimal first response is Beaver, and the original doubler should pass the beaver. Tests repeat the entire permitted chain with mirrored players, verify accepted-stake pass units and error grading, check Jacoby changes checker evaluation, and exercise money/match no-cube evaluation.
